reqdb: the CLI for agents

One file, no dependencies, Node 18 or newer. It reads requirements, tests and accelerators from Requirements DB and lets your coding agent record what it implemented, what is in progress and what is still pending, in a project you own. The default output is plain text (easy for an agent to read); add --json for machines. There is no MCP server on purpose: a CLI is enough, works in any agent and in CI.

Install

curl -fsSL https://joderestatodocogido.com/proyectos/requirements-db/app/reqdb.mjs -o reqdb.mjs
node reqdb.mjs version

Or without downloading anything: npx github:luismariagonzalez/db_public_requirements version (replace version with any command below). In the examples we write reqdb; use whichever of the two forms you installed.

Reading needs no account

Searching and reading is anonymous (rate limited). Projects need an API key: sign in on the website, open Account, create a key (it starts with rq_) and store it once:

reqdb login --key rq_xxxxxxxx      # saved in ~/.config/reqdb/config.json (mode 600)
# or, for CI and agents: export REQDB_KEY=rq_xxxxxxxx

Agent workflow (the short version)

reqdb agent                               # prints the instructions your agent should follow
reqdb init --name "My app" --category saas-b2b --max-priority 2
reqdb pull -o REQUIREMENTS.md --hide-done  # the brief to hand to the agent
reqdb mark done auth-email-password test:auth-lockout accelerator:clerk
reqdb mark planned password-reset --note "next sprint"
reqdb status                              # done / in progress / pending
reqdb check --max-priority 1              # exit 1 while any P1 is pending

init creates the project on the server and writes .reqdb.json in the current folder, so later commands know which project you mean. Commit that file; never commit your key.

Commands

CommandWhat it does
categories [--type T] [--q text]Audiences, domains, software categories, app types, flows (sign-up, sign-in, settings…) and cross-cutting topics you can filter by.
search [text]Hybrid (semantic + keyword) search of requirements. Options: --category a,b, --max-priority N, --kind functional|technical, --sort priority|copies|relevance (most copied by people and agents), --tests, --accelerators, --limit N.
show <slug>One requirement with its tests and accelerators.
tests [text]Search tests. Same --category and --max-priority filters.
accelerators [text]Libraries and services that speed up a requirement. Also --model open_source|proprietary|saas, --platform p and --sort relevance|popularity (GitHub stars and monthly downloads from the official registry, shown next to each result).
login --key rq_…Store your API key. logout removes it.
init --name NCreate a project and write .reqdb.json. Options: --category, --max-priority.
projects, use <id>List your projects; select one for this folder.
pull [-o file]Write the Markdown brief. Options: --hide-done, --no-tests, --no-accelerators.
mark <status> <item…>Status is done, in_progress, planned or skipped. Items: slug, test:slug, accelerator:slug. Optional --note.
statusWhat is done and what is pending in the current project.
check [--max-priority N]Exit code 1 if requirements up to priority N are still pending. Built for CI.
suggest <text>Send a suggestion (--about slug, --type requirement|test|accelerator). A person reviews it.
agentPrint the standing instructions an agent should follow: record done, in progress and planned work in the project.

Global options

--json machine-readable output · --url <base> another server · --key <key> · --project <id> · --quiet · -h/--help · --version.

Configuration precedence, highest first: flags, environment (REQDB_URL, REQDB_KEY, REQDB_PROJECT), .reqdb.json in the folder, ~/.config/reqdb/config.json.

Exit codes

CodeMeaning
0OK.
1Pending work (check) or the server refused the request.
2Wrong usage: unknown command or missing argument.
3API key missing or invalid.
4Rate limited: wait and retry.
5Network or server error.

In CI

# .github/workflows/requirements.yml (step)
- run: node reqdb.mjs check --max-priority 1
  env:
    REQDB_KEY: ${{ secrets.REQDB_KEY }}
    REQDB_PROJECT: ${{ vars.REQDB_PROJECT }}

Good to know

  • Requirements say what an app must do, never where (screens, buttons): that is your agent’s decision.
  • The database content is in English; this documentation and the interface are in English and Spanish.
  • The content is under the Content Terms: free for your own software, no bulk extraction. The CLI code is MIT.
  • Prefer HTTP? The same features are in the REST API.

reqdb: el CLI para agentes

Un solo fichero, sin dependencias, Node 18 o superior. Lee requisitos, tests y aceleradores de Requirements DB y permite que tu agente de programación anote qué ha implementado, qué está en curso y qué queda pendiente, en un proyecto tuyo. La salida es texto plano por defecto (fácil de leer para un agente); añade --json para máquinas. No hay servidor MCP a propósito: un CLI basta, funciona en cualquier agente y en CI.

Instalación

curl -fsSL https://joderestatodocogido.com/proyectos/requirements-db/app/reqdb.mjs -o reqdb.mjs
node reqdb.mjs version

O sin descargar nada: npx github:luismariagonzalez/db_public_requirements version (cambia version por cualquier comando de abajo). En los ejemplos escribimos reqdb; usa la forma que hayas instalado.

Leer no necesita cuenta

Buscar y leer es anónimo (con límite de uso). Los proyectos necesitan una clave de API: inicia sesión en la web, abre Cuenta, crea una clave (empieza por rq_) y guárdala una vez:

reqdb login --key rq_xxxxxxxx      # se guarda en ~/.config/reqdb/config.json (modo 600)
# o, para CI y agentes: export REQDB_KEY=rq_xxxxxxxx

Flujo del agente (versión corta)

reqdb agent                               # imprime las instrucciones que debe seguir tu agente
reqdb init --name "Mi app" --category saas-b2b --max-priority 2
reqdb pull -o REQUIREMENTS.md --hide-done  # el documento para pasar al agente
reqdb mark done auth-email-password test:auth-lockout accelerator:clerk
reqdb mark planned password-reset --note "próximo sprint"
reqdb status                              # hecho / en curso / pendiente
reqdb check --max-priority 1              # sale con 1 mientras haya algún P1 pendiente

init crea el proyecto en el servidor y escribe .reqdb.json en la carpeta actual, para que los comandos siguientes sepan de qué proyecto hablas. Sube ese fichero al repositorio; nunca subas tu clave.

Opciones globales

--json salida para máquinas · --url <base> otro servidor · --key <clave> · --project <id> · --quiet · -h/--help · --version.

Orden de la configuración, de mayor a menor: opciones, entorno (REQDB_URL, REQDB_KEY, REQDB_PROJECT), .reqdb.json de la carpeta, ~/.config/reqdb/config.json.

Códigos de salida

CódigoSignificado
0Correcto.
1Trabajo pendiente (check) o el servidor rechazó la petición.
2Uso incorrecto: comando desconocido o falta un argumento.
3Falta la clave de API o no es válida.
4Límite de uso: espera y reintenta.
5Error de red o del servidor.

Conviene saber

  • Los requisitos dicen qué debe hacer una app, nunca dónde (pantallas, botones): eso lo decide tu agente.
  • El contenido de la base está en inglés; esta documentación y la interfaz están en inglés y español.
  • El contenido está bajo los términos del contenido: libre para tu propio software, sin extracción masiva. El código del CLI es MIT.
  • ¿Prefieres HTTP? Las mismas funciones están en la API REST.
